# 明细主页面架构

`mingxi` 是小程序的主壳页面。这里保留原有单页交互模型，但按职责拆分代码，避免业务继续堆积在入口文件中。

## 目录职责

- `mingxi.js`：只组装页面状态、依赖和功能模块，不承载业务实现。
- `model/create-initial-data.js`：页面初始状态的唯一入口。
- `features/`：页面行为，按生命周期、报表、记账与结清、账本、设置、自定义、加密、引导、语音助手、会员拆分。
- `services/`：仅服务本页面的纯业务辅助能力。
- `views/`：WXML 视图片段；`tabs/` 是五个主 Tab，`overlays/` 是弹层与引导。
- `styles/`：按视图域拆分的 WXSS，导入顺序由 `mingxi.wxss` 统一控制。

## 边界约定

1. 页面功能通过 `utils/api.js` 访问数据、存储和网络，不在视图或功能模块中直接拼接后端接口。
2. WXML 的事件名属于页面公共契约；拆分功能模块时不能随意改名。
3. 跨页面共享的翻译和分类默认值放在 `utils/`，页面状态使用副本，避免共享可变数据。
4. 新功能优先放入已有功能域；只有形成独立职责时才新增模块。

在项目根目录运行 `node scripts/check-frontend.js`，可检查页面注册、重复方法、WXML 事件绑定、视图片段引用、样式引用和主包页面完整性。
